## 📋 Phase 2: 数据层优化 (建议下周启动)

| 工作项 | 具体任务 | 优先级 | 预计工作量 |
|--------|----------|--------|-----------|
| **增量嵌入** | 只重新嵌入变化的 chunk，基于 mtime + hash 判断变化，避免大文件全量重嵌入 | 高 | 2-3 天 |
| **嵌入缓存** | LRU 缓存 {text_hash -> embedding}，避免重复计算，命中率监控 | 高 | 1-2 天 |
| **Ledgers/Plans/Brainstorms 自动同步** | 配置自动扫描并索引 thoughts/ledgers/ 和 thoughts/brainstorms/ | 中 | 2 天 |

**预期收益**: 索引速度提升 80%，减少 Ollama 调用

---

## 📋 Phase 3: 智能化 (建议下下周)

| 工作项 | 具体任务 | 优先级 | 预计工作量 |
|--------|----------|--------|-----------|
| **时间衰减权重** | 新记忆权重更高: score = distance × decay(days_ago)，推荐 30天半衰期 | 中 | 1-2 天 |
| **MMR 多样性算法** | Max Marginal Relevance，避免结果全来自同一文件，平衡相关性和多样性 | 中 | 2-3 天 |
| **反馈循环** | POST /api/feedback {id, helpful}，记录有用/无用结果用于排序优化 | 低 | 3-4 天 |

**预期收益**: 搜索质量质变，用户获得更相关、更及时的结果

## 💡 决策建议

### 路线 A: 按优先级顺序 (推荐)
```
Phase 2 → Phase 3 → Phase 4
(性能优化 → 智能化 → 运维)
```
**理由**: 性能优化是智能化的基础，先让系统快起来，再上智能算法

### 路线 B: 并行开发
```
Phase 2 (增量嵌入) + Phase 3 (时间权重) 同时进行
```
**理由**: 两个功能无依赖关系，可以并行节省整体时间
